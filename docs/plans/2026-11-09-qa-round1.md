# QA round 1: server turns, music, facing, bare minimum (2026-11-09)

This round runs a subset of `docs/plans/2026-11-04-qa-handoff.md`. Step IDs (A.1, C.3, G.1) are the IDs of that handoff, so its intake still applies. The handoff stays the full list.

Owner scope (2026-11-09): voice and music only, most critical UX first. No conversation test in `robot` turns: earlier rounds already showed that mode is inefficient and clunky. The robot runs `main` with PR 200 (owner statement). About 25 minutes.

Owner rules: an agent does not move the motors, does not start or restart RoboEmot, and asks before any SSH write to the robot.

## Reports

1. Open `http://192.168.88.198:8042/api/debug` in a browser tab that is logged in to the web UI.
2. Save the page as JSON into `~/Downloads/roboemot-qa/` with the file name of the block.

Counters and latency lists are per process. The restart in setup makes the first report clean. Later blocks read as a difference against the report before them.

## Setup (5 minutes)

1. Run `python scripts/run_on_robot.py --restart --host 192.168.88.198`. Wait about 2 minutes before you talk.
2. In Settings, check `voice.barge_in.onset_enabled` is on.
3. In Settings, set `voice.facing.enabled` off.
4. In Settings (admin PIN), set `voice.realtime_route.turns` to `server`.
5. In Settings (admin PIN), set `voice.realtime_route.audio_gate` to `server_gates`. The handoff omits this key. Without it the robot sends no audio in server mode.

## Block 1: conversation, server turns (6 minutes), report `1-server.json`

Steps: A.1, A.2, A.4 to A.8, A.9 and A.10 (server half), shortened to 6 minutes. Face the robot at about 1 m.

1. Ask 5 ordinary questions. Let each answer finish.
2. Say "ciao Neve" 5 times, with a pause after each (A.6).
3. Ask for a long story. Talk over the robot. Do this 5 times (A.9).
4. Ask for something that uses a gesture during a long answer, and interrupt it (A.5).
5. Play a TV clip for 30 s. Take one phone call in front of the robot (A.1).
6. In Settings, set `turns` back to `robot` and `audio_gate` back to `addressed`, after you save the report.

| Check | Pass | Debug key |
| --- | --- | --- |
| Route is up | connected, no local fallback | `realtime_route.state`, `local_fallbacks` |
| The mode ran | count above 0 | `latency_ms.by_turns.server.turn` |
| Latency | record p50 and p95 | `latency_ms.by_turns.server` |
| Listener keeps up | `lag_max_s` under 1 s, `dropped_s` close to 0 | listener `lag_max_s`, `dropped_s` |
| One answer per question | no sentence twice | `realtime_route.responses.completed` against `conversation.turns` minus `skipped` |
| Name hint | Live transcript reads "Neve" | `realtime_route.transcription_hint` `sent`, `refused` |
| TV and phone | no answer | `realtime_route.skipped` |
| Interruption | p95 at most 1.0 s, each real one stops the robot | `by_turns.server.onset_to_stop`, `bargein.barge_ins` |
| Each confirmed barge-in answers | `server_unanswered` stays 0 | `conversation.server_unanswered`, `realtime_route.server_responses` |
| Own voice | `playback_streams` stays 0 while only the robot speaks | `bargein.barge_ins.playback_streams` |
| No damage after a stop | `errors_unrelated` does not rise | `realtime_route.errors_unrelated` |

Owner judgement: the voice, the listening cue, answers cut short, stray end words (A.8), a cue over the answer (A.10), a stop with nobody talking.

## Block 2: music (9 minutes), report `2-music.json`

Steps: G.1 (Q1) and G.2. This block runs in `robot` turns, because Q1 checks the wake word path, and `server` turns do not apply the wake word policy.

1. Play a song for 3 minutes. Talk over it. Say the wake word "Neve" 10 times and count the answers.
2. Speak without music for 3 minutes.
3. Play TV for 3 minutes.

| Check | Pass | Debug key |
| --- | --- | --- |
| CPU timer works | median above 0 and below 10 | `roboemot.voice.music.cost_ms_per_audio_s` |
| Music cost | median at most 10 ms per audio second (1 % of one core), at most 20 with an owner OK | same key |
| Speech is not music | no `rejected_music` in the speech minutes | wake `decisions.rejected_music` |
| Lyrics | no answer to the lyrics | owner judgement |
| Wake over music | hits out of 10 | owner count, wake `decisions.wake_word` |

A pass opens the dance slices 2 to 4 of `docs/plans/2026-11-04-music-dance.md`. A cost above 20 ms per audio second: retry with a longer hop and fewer bands first.

## Block 3: facing (5 minutes), report `3-facing.json`

Steps: C.1, C.2, C.3, C.6, C.7, 3 times each instead of 5.

1. In Settings, set `voice.facing.enabled` on. This also restores the profile value: a saved `off` stops the next `--cloud-voice` install.
2. In Settings, set `webui.live.video_landmarks` on. In the Live preview, check the 5 dots sit on your eyes, nose and mouth.
3. Run the steps at 50 cm, with your face in view.
4. Set `webui.live.video_landmarks` off.

Pass: C.1 answers, C.2 does not, C.3 answers. C.1, C.6 and C.7 together decide the cause (handoff, "How to read the results").

Debug keys: `roboemot.voice` `decisions`, `direction.facing.recent[]`, `roboemot.vision` `faces[]`, `frame`.
