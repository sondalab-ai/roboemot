# M3 Voice — epic plan

## Context

SPEC §14 milestone M3: capture with AEC, VAD, fast path, ASR, TTS, barge-in, LLM router with skills.
Exit: Italian and English conversation within the §13 latency budgets (end of speech → fast-path
reaction ≤ 300 ms; → first TTS audio ≤ 2.0 s on cm4; barge-in → TTS stop ≤ 200 ms).

Today only `voice/prosody.py` (`compose_delivery`, `to_piper`, `to_openai`, mood tags), the LLM router
(`llm/router.py`), `system_prompt`/`trim_history` (`llm/prompt.py`) and the persona exist.
`ReachyAudio` (`roboemot_reachymini/audio.py`) reads the mic and emits only RMS to the reflex engine.
No playback, VAD, ASR, TTS, sessions or skills. Carried-in items:

- Reflex: the loud-onset startle cannot ignore the robot's own voice (`reflex/engine.py:176`, no gate;
  only `DoASource.mute` exists, `world.py:146`, never called).
- `get_audio_sample` hands each chunk to one reader → the voice pipeline must take audio through
  ReachyAudio, which today also drops stale chunks (fine for reflexes, wrong for ASR).
- TODO.md persona items: build requests with `system_prompt` + `build_messages`; pass
  `persona.effects` to `compose_delivery`; `conversation.history_turns` cap.

Facts found in the installed SDK (reachy-mini 1.12): `media.start_playing / push_audio_sample /
stop_playing`, `media.audio.clear_player()` (flushes queued playback → barge-in); on the Wireless the
mic goes through the XMOS AEC loopback (`audio_gstreamer.py:147`), elsewhere through webrtcdsp. So
RoboEmot does not ship its own AEC in M3; it adds a half-duplex "speaking" gate as the safety net and
leaves the residual-echo measurement to the robot (§15).

## Cross-cutting rules (from review)

- **Sample rates are read, never assumed.** The hub reads `get_input_audio_samplerate()` /
  `get_input_channels()`; the speaker resamples every backend (Piper voice rate from its `.onnx.json`,
  usually 22.05 kHz; OpenAI 24 kHz) to `get_output_audio_samplerate()`.
- **Latency is measured from the last speech frame**, not from the endpoint decision. The reference is `SpeechEnd.last_speech_stamp`: the start of the last frame judged speech at the off threshold (conservative, up to one 32 ms frame early); the endpoint is declared `end_silence` frames plus one frame after it. The fast-path
  reaction fires from partials before `voice.vad.end_silence_ms` runs out; the end-silence default is
  chosen against the 2.0 s first-audio budget (route `first_token_timeout_s` is already 1.5 s).
- **Piper runs as one persistent subprocess** with a small per-sentence request protocol (text,
  `length_scale`, noise, volume); never one process per sentence.
- **Children (user decision 2026-10-17, replaces the SPEC's "no conversation while a minor is
  present"):** the robot talks to children, appropriately.
  - While a minor is present only routes with `allowed_for_minors: true` are eligible (the per-route
    default stays false; the admin clears a route, e.g. the LAN model). The request carries the minor
    content rules of the safety block (exists in `system_prompt(minor_present=True)`) and the child
    register.
  - No cleared route → short child-safe lines from a built-in, per-language set (greeting, its name,
    "ask a grown-up"), never silence and never an uncleared route.
  - Shorter replies: new `register.*.max_reply_sentences` (unset = `conversation.max_reply_sentences`,
    3); child register default 2 (my call).
  - §12 output filter before TTS while a minor is present (blocklist per language, configurable;
    a filtered sentence is replaced by a built-in line).
  - A minor appearing mid-answer: stop TTS, cancel the stream if the route is not cleared, continue
    under the minor rules on the next turn.
  - SPEC edits in slice 5: §8 (LLM router, OpenAI-compatible routes), §12 Behaviour, §15 question
    "adults-only in v1?" resolved.
- New field `voice.enabled` (does not exist yet), added in slice 1.

## Slices (integration branch `epic/m3-voice`, one PR per slice, one merge to `main`)

Each slice: config fields in `config/schema.py` with default/unit/range (SPEC 11A), new modules added
to `BEHAVIOUR_MODULES` in `tests/test_no_magic_numbers.py`, unit tests with fake SDK media, ruff +
pytest green, SPEC section cited in commits. Privacy: no audio, transcript text or embeddings in logs.

1. **Audio hub + speaking gate** (§4A, §8 stage 1, §10)
   - `roboemot_reachymini/audio.py`: one reader of `get_audio_sample`, fans out to (a) the reflex RMS
     sink with the existing stale-drop rule, (b) a lossless bounded voice queue (mono 16 kHz float32,
     drop counter in `snapshot()`). Starts when `reflexes.audio.enabled` or `voice.enabled`.
   - `ReachySpeaker`: `start_playing`, chunked `push_audio_sample`, queued-duration tracking, `stop()`
     via `clear_player`.
   - Core `voice/activity.py` `SpeechActivity`: "robot is speaking until stamp + `voice.echo_tail_ms`".
     Reflex engine skips `loud_onset` while speaking; the app calls `DoASource.mute` from it.
   - Closes both reflex items. Tests: `test_audio.py`, `test_app_reflex.py` (no startle during playback,
     startle again after the tail).
2. **Voice models + VAD** (§8 stage 2)
   - Generalise the model fetcher (`vision/models.py`) to a voice registry `voice/models.yaml`
     (Silero VAD, Vosk small it/en, Piper it/en voices), add zip extraction for Vosk, sha256 as today;
     `roboemot models fetch --voice`. New `voice` extra (`vosk`, `onnxruntime`).
   - `VADBackend` protocol; Silero ONNX backend; endpointing (`voice.vad.*`: threshold, min speech,
     end silence). Test-only energy VAD.
3. **ASR + fast path** (§8 stages 3–4)
   - `ASRBackend` protocol, Vosk streaming backend (partials + final), one active language (speaker's
     profile, else `conversation.language`).
   - Keyword spotting on partials (robot name, stop, no, greetings; per-language lists in config) →
     `hint_speaker` (turn toward voice), appraisal events (new names in `APPRAISAL_EVENTS`). Wake word =
     `voice.wake_word` spotted on Vosk partials (no new model), applied per the existing
     `voice.wake_word_policy` (default `unless_enrolled_in_view`: strangers must say it).
   - Prosody features (loudness, pitch, rate) → affect impulses. Speech counts as interaction for
     `idle.long` and circadian presence. Publishes `percept.utterance`.
4. **TTS** (§8 stage 7, Voice/expressivity/mood)
   - `TTSBackend` protocol; Piper as a separate process (GPL-3.0) streaming raw PCM; OpenAI speech
     backend (PCM 24 kHz → 16 kHz, route rules: timeout, minors flag, Piper fallback when offline).
   - Streaming sentence splitter, `llm_tagged` mood tags, `compose_delivery(..., persona=effects(...))`
     (TODO item). Installer puts Piper in its own venv under the data folder, recorded for uninstall.
5. **Conversation worker** (§8 stage 6, Conversation state)
   - Worker on its own thread/loop (pattern: `persona/llm_traits.py` `TraitsWorker`), sharing route
     budgets with it (`Router.adopt_budgets`).
   - Sessions (start on engagement, end after `session_timeout_min`), RAM-only history capped by
     `conversation.history_turns`; requests from `system_prompt` + `build_messages` with the
     persona-shaped register (TODO item); new profile and scene summary builders under their caps.
   - `build_messages` keeps assistant `tool_calls` and `tool` messages. Children per the cross-cutting
     rule (cleared routes, built-in lines, shorter replies, output filter, mid-answer switch; tests for
     each). `Offline` → `OfflineResponder`; `NoRouteAvailable` → register fallback line.
   - Speaks from the first complete sentence. Affect `new_turn()` per turn.
6. **Barge-in + skills** (§8 stage 8, §11)
   - Barge-in: VAD speech during playback above `voice.barge_in.*` → `ReachySpeaker.stop()`, cancel the
     LLM stream (`aclose`, budget still charged); the speaking gate's "until" resets on stop. Test: the
     fake mic receives the robot's own playback → no barge-in (the gate is the only guard on robots
     without hardware AEC).
   - `@skill` decorator, JSON schema from type hints, `llm_visible`; default skills `play`, `look_at`,
     `express_emotion` (`AffectEngine.llm_impulse`), `remember_preference` (asks to confirm, writes the
     registry), `stop_talking`. Router yields each `ToolCall` as soon as it is complete; bounded tool
     rounds (`conversation.max_tool_rounds`).
7. **Route conformance test** (§8 OpenAI-compatible routes) — independent, can run in parallel
   - Core `check_route`: streaming, tool round trip, first-token latency, Italian output.
     `roboemot llm check <route>` CLI and a PIN/CSRF-gated web UI action. My call: advisory in M3
     (result shown and stored per route, does not gate it); gating needs a route-enable flow the web
     UI does not have yet.
8. **Exit test + report** (§14)
   - Replay test (`@pytest.mark.models`): short recorded it/en WAV fixtures → hub → VAD → ASR → mocked
     SSE route with set latency → Piper → fake speaker. Asserts the three latency budgets and a
     barge-in. `docs/eval/m3.md`, SPEC §14 status, §15 robot items (residual echo, AEC on Wireless,
     chunk size/rate, Italian OpenAI voice quality), TODO.md updated.

Order: 1 → 2 → 3; 4 after 1; 5 after 4 (uses a fake ASR source until 3 lands); 6 after 5; 7 any
time; 8 last.

## Cost estimate

8 slices; per slice one Sonnet author + one Sonnet reviewer (≈16 agents), plus an Opus security review
on slices 5–7 (LLM requests, tools writing the registry, minors gate, web UI). ≈19 agent runs.
Slices 4 and 7 can run in parallel worktrees. Budget check-in after each phase (1–3, 4–6, 7–8).

  for slices 2–4 and 8 (needs `roboemot models fetch --voice`); `pytest -m sim` stays green
  (sim runs without media).
- Exit: slice 8 replay test locally and in CI nightly; the real conversation on Neve is a §15 item for
