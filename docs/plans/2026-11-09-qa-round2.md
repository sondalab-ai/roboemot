# QA round 2: head at rest, voice fixes, music, dance (2026-11-09)

This round runs after the music-dance epic lands on `main`. Step IDs (C.3, F.5, G.1) are the IDs of `docs/plans/2026-11-04-qa-handoff.md`. Round 1 is `docs/plans/2026-11-09-qa-round1.md`.

Owner rules: an agent does not move the motors, does not start or restart RoboEmot, and asks before any SSH write to the robot. The SSH password is never stored.

Order: hardware safety first, then what the owner asked for. About 75 minutes. Stop after any block and send what you have.

`turns: server` is not in this round. Round 1 showed that the default gates stream a private conversation. A retest with `server_gates: [music, at_face, facing]` waits for an owner OK.

## Reports

1. Open `http://192.168.88.198:8042/api/debug` in a browser tab that is logged in to the web UI.
2. Save the page as JSON into `~/Downloads/roboemot-qa/` with the file name of the block.

Counters are per process. Later blocks read as a difference against the report before them.

## Setup (15 minutes)

1. On the Mac: `git pull --ff-only` on `main`, then `pip install --no-deps -e packages/roboemot-core -e packages/roboemot-reachymini`.
2. In Settings, check that `voice.facing.enabled` is on. A saved `off` stops the next `--cloud-voice` install.
3. Run `python scripts/install_on_robot.py --cloud-voice --overclock --host 192.168.88.198`. Both flags are needed: an install without `--overclock` removes the 1.8 GHz setting.
4. Run `python scripts/run_on_robot.py --host 192.168.88.198`. Wait about 2 minutes before you talk.
5. In Settings, check these values:
   - `voice.realtime_route.turns` is `robot` and `audio_gate` is `addressed`;
   - `voice.barge_in.onset_enabled` is on;
   - `voice.barge_in.sustain_ms` is 1000;
   - `dance.enabled` is on;
   - write down `voice.vad.min_speech_ms` (round 1 inferred 96 ms or less; the default is 200).

## Block 1: head at rest (10 minutes), report `1-rest.json`

Steps: F.5, F.6. This block protects the hardware. Run it first.

1. In Settings, set `circadian.nap_after_s` to 300 (the lowest allowed value).
2. Leave the room, or stay out of the camera view, and say nothing to the robot for 5 minutes.
3. When the robot rests, watch the head for 2 minutes. If the head knocks on the body, stop and send the report.
4. Save the report. Set `circadian.nap_after_s` back to 1800.
5. Optional: F.6, the pitch steps of the handoff.

| Check | Pass | Debug key |
| --- | --- | --- |
| The robot rests | state `resting`, reason `nap` | `roboemot.circadian` |
| Head stays still | no knock (owner) | |
| Pose follows | `head.pitch` measured within about 1 degree of `commanded` | `roboemot.motion` |
| No silent press | `steady_offsets` does not grow | `roboemot.motion` |
| No yield | `external_events` does not grow, `unreachable` stays 0 | `roboemot.motion` |

## Block 2: voice fixes (8 minutes), report `2-voice.json`

Steps: the three fixes of round 1. Face the robot at 50 cm.

1. Say "Neve, raccontami una storia lunga". While the robot talks, say one short word, under 1 s, such as "sì". Do this 5 times over several answers.
2. While the robot talks, talk for 2 s or more. Do this 5 times.
3. While the robot talks, say "basta". Do this 3 times.
4. Say "Neve, come stai?" 5 times. Let each answer finish.

| Check | Pass | Debug key |
| --- | --- | --- |
| Short word | the voice ducks and returns, the answer finishes | `roboemot.voice` `bargein.sustain.released` |
| Long speech | the robot stops about 1 s after you begin | `bargein.sustain.held`, `bargein.triggers` |
| Stop word | the robot stops at once, with no 1 s wait | `bargein.keyword_triggers` |
| Listening blip | you hear it on each turn (owner) | |
| Name path | 5 answers out of 5, record the slowest answer | wake `decisions`, Live transcript |

Round 1 had an answer of 6.5 s and one miss. Write down each miss with the time.

## Block 4: dance to music (15 minutes), report `4-dance.json`

Steps: Q2 and Q3 of `docs/plans/2026-11-04-music-dance.md`. Open the Live tab before you begin. Every dance value is a first guess. Stay near the robot.

1. Play a song at about 100 to 120 BPM. Watch for 2 minutes.
2. Play a song above 140 BPM for 1 minute.
3. Stop the song. Wait 15 s.
4. Play the first song again. Say "Neve, come stai?" and let the robot answer over the music.
5. Tune in Settings if a move looks wrong, and write down each value: `dance.lead_ms`, `dance.bob_deg`, `dance.sway_deg`, `dance.accent_deg`, `music.min_periodicity`.

| Check | Pass | Debug key |
| --- | --- | --- |
| Starts | the dance fades in after the music is confirmed, with no jump | `roboemot.voice` `dance.started`, `dance.source` is `room` |
| On the beat | the head dips on the beat (owner) | tune `dance.lead_ms` |
| Fast song | the head moves on fewer beats and never hurries (owner) | |
| No jump | no sudden head step during a song (owner) | |
| Signs | the bob dips, the sway tilts and turns to one side, the antennas flick outward (owner) | |
| Yaw | the turn in the sway is not too much (owner) | the map sets it equal to the roll, 2 degrees |
| Stop | `music.stopped` within 8 s (`music.release_s`) of the end, then the dance fades out | `roboemot.voice.music` |
| While it answers | a smaller move continues; the head pitch belongs to the speech | owner |
| No yield | `external_events` does not grow while it dances | `roboemot.motion` |
| Live card | the circle pulses on the beat, BPM and confidence match the song, the bars move and shrink while it speaks | owner |

Known limits, not a fail:
- an answer longer than 30 s (`music.blind_hold_s`) stops the dance;
- the Live card still reads "attiva" while an external control yield holds the motors;
- a song detected above 120 BPM once stays at quarter time until the estimate falls below about 109 BPM.
